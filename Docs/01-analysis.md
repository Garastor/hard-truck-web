# 01. Аналіз оригінальної гри та ресурсів

## 1. Що є в наявності

Папка `Game/Hard Truck/` (≈660 МБ) — встановлена гра + копія CD1 (`Hard_Truck_CD1/`) + архів `HardTruck.zip` (дубль).

| Компонент | Файли | Примітка |
|-----------|-------|----------|
| Виконуваний файл | `HTruck.exe` (1.8 МБ) | Win32, **Watcom C++**, 06.04.1999; DirectDraw/Direct3D (DX5–6), DirectInput, DirectSound, DirectPlay (мережа). Детально: [07-reverse-engineering.md](07-reverse-engineering.md) |
| Локації (6 шт.) | `CIRCUIT/`, `COUNT/`, `MOUNT/`, `NIGHT/`, `TRIAL/`, `MENU3D/` | у кожній: `*.B3D`, `*2.B3D`, `*.RMP`, `*3.RMP`, `*3.OVL` |
| Ресурси інтерфейсу | `LOAD.RES` (7.5 МБ) | маски/текстури меню, індикатори, курсор |
| Шрифти | `MENU.FON`, `large.fon`, `MENU.SFT`, `D1.SFT`; на CD — `MENU.TGA`, `LARGE.TGA` | растрові шрифти |
| Фізика вантажівок | `TRUCK.TCH` (текст, INI-подібний) | вузли моделей, колеса, фари, кабіна, шкали приладів |
| Налаштування | `truck.ini` / `TRUCK.INP` | рендер, параметри авто, ефекти, гучність |
| Запис демо | `DEMO.TR` | запис заїзду (реплей) — корисний як еталон |
| Профіль гравця | `ВОДИТЕЛЬ.pl` | збереження/профіль |
| Відео | `HTruck.avi` (75 МБ) | Cinepak + PCM → конвертувати ffmpeg у H.264/AAC |
| Довідка | `HTruck.hlp` | WinHelp — тексти правил, керування (джерело для UI-текстів) |
| **Музика** | **відсутня** | була CD-Audio доріжками на диску. У `Hard_Truck_CD1/` лише файлова частина диска: аудіодоріжки CD не є файлами, тож при копіюванні вони не потрапили. Потрібен рип фізичного диска (EAC/CDex) або образ `.cue/.bin` |

Вантажівки (з `TRUCK.TCH` та `*.OVL`): **ЗіЛ, Volvo, Freightliner, Iveco, КамАЗ, Kenworth** та ін.
У кожної — окремі вузли коліс, фар, кабіни (вид з кабіни), маска приладової панелі.

## 2. Формати файлів — що підтверджено

### 2.1 RMP / RES — архів ресурсів ✅ (перевірено скриптом `tools/probe/probe_rmp.py`)

Послідовність секцій. Кожна секція: `"<НАЗВА> <кількість>\0"`, далі елементи:

- **файлові секції** (`PALETTEFILES`, `SOUNDFILES`, `BACKFILES`, `MASKFILES`, `TEXTUREFILES`):
  `імʼя\0` + `uint32 LE розмір` + `дані[розмір]`
- **рядкові секції** (`COLORS`, `MATERIALS`, `SOUNDS`): масив рядків `\0`

Приклад `CIRCUIT/CIRC.RMP`: 1 палітра, 20 WAV, 4 фони (небо), 489 масок, 249 текстур, 52 кольори, 387 матеріалів, 26 звуків. Файл розбирається до останнього байта.

Синтаксис матеріалу: `імʼя параметр значення …`, напр. `throw ttx 2 RotPoint 0.5 0.5 rot 400`.
Параметри: `tex N` / `ttx N` (текстура з прозорістю) / `col N` (колір), `transp`, `reflect`, `specular a b`,
`rot` (обертання), `RotPoint`, `move`, `env`, `noz`, `nof`, `notile`, `coord`, `att`, `power`.

### 2.2 TXR — текстура ✅

Сигнатура `00 01 01 00 …` = **TGA тип 1** (8 біт, палітра 256×24 біт). Отже TXR — по суті TGA з палітрою;
16-бітні варіанти мають додаткові чанки `LOFF` / `PFRM` (маски каналів) / `LVMP` (міпмапи).

### 2.3 MSK — маска/спрайт ✅ (за документацією спільноти)

Сигнатури `MSK8` / `MASK` / `MASKW`. 8-бітні зображення з палітрою, RLE-подібне стиснення.
Використовуються для HUD, приладів, дощу на склі, меню.

### 2.4 PLM — палітра ✅

Сигнатура `PLM\0` + чанки `PALT` (256×RGB) та, ймовірно, таблиці освітлення/туману.

### 2.5 B3D — сцена (геометрія + логіка) 🟡 частково

Заголовок (усі розміри/зсуви у **dword**, ×4):
`"b3d\0"`, розмір файлу, зсув/розмір списку матеріалів, зсув/розмір даних.
Список матеріалів: `uint32 N` + `N × char[32]` (імена → шукаються в MATERIALS з RMP).
Дані: маркер `111` … `222`; блоки `333 … 555`; `444` — розділювач перемикачів (LOD, день/ніч).
Блок = `char[32] імʼя` + `uint32 тип` + параметри + вкладені блоки.

Гістограма типів блоків у `CIRC.B3D` / `CIRC2.B3D` (скрипт `tools/probe/probe_b3d.py`):

| Тип | К-сть | Імена-приклади | Значення (за спільнотою HT2 + наші спостереження) |
|-----|------|----------------|------|
| 2, 3, 5 | сотні | `sort_01`, `road_999`, `Background_object` | групи / вузли ієрархії |
| 4 | ~260 | `Wiper`, `FreiWheelFR`, `lens1` | посилання на вузол / інстанс |
| 6, 7 | ~2000 | `AnmObj0203`, `road_099`, `TachoStr` | **геометрія: вершини + UV** (тип 6 — лише в HT1) |
| 8, 28, 35 | ~2800 | — | **полігони** (індекси, UV, матеріал) |
| 9, 10 | сотні | — | тригери / **LOD** за відстанню |
| 13 | ~45 | `event_finish`, `restart_001`, `tunnel_rain` | **ігрові події** (фініш, рестарт, дощ у тунелі) |
| 18 | ~560 | `anmobj0203001`, `link_sun` | посилання / інстанси обʼєктів |
| 19 | 36 | `room_001`…`room_999` | **«кімнати»** — сектори світу (поділ карти) |

**Висновок:** B3D у HT1 дуже близький до HT2 — для HT2 є часткові специфікації та імпортери;
відмінності (тип 6 тощо) доведеться добити самостійно через 010 Editor/ImHex та порівняння з картинкою оригіналу.

`*.B3D` vs `*2.B3D`: ймовірно, перший — машини/обʼєкти, другий — траса/оточення
(у `CIRC2.B3D` є `road_099`, `SkyDomeKey`, `sun_s*`). Підтвердити у Фазі 1.

### 2.6 OVL — текстові описи кластерів ✅

`CLUSTER імʼя … END`, `OVERLAY … END` — групування текстур (небо, дощ, кабіни конкретних вантажівок).
Потрібні для завантаження текстур кабіни лише обраної вантажівки.

### 2.7 TCH — техніка/фізика ✅ (текст)

INI-секції `[NODESn]` для кожної вантажівки: імена вузлів у B3D (колеса, фари, кабіна, габарити),
маска панелі, шкали тахометра/спідометра, кути огляду з кабіни. Решта файлу (≈58 КБ) — числові
параметри динаміки (маса, двигун, КПП тощо) — **головне джерело для фізики**.

### 2.8 Чого ще не знаємо (досліджувати у Фазі 1)

- Точна семантика блоків B3D типів 9, 10, 14, 16, 17, 29, 37 та прапорців полігонів.
- Формат `DEMO.TR` (реплей) та `ВОДИТЕЛЬ.pl` (профіль).
- Ігрова логіка, «зашита» в `HTruck.exe`: правила заїздів/доставки, ШІ суперників, поліція,
  економіка, формули фізики. Джерела: реверс `.exe` ([07](07-reverse-engineering.md)), довідка `HTruck.hlp`,
  гра в оригінал (через dgVoodoo2).
- Чи `MENU3D` — це 3D-сцена головного меню (так, судячи з назви) — відтворити як живе меню.

## 3. Висновки для порту

1. Усі ресурси **палітрові та низькополігональні** (1998 р.) — ідеально лягають на мобільний WebGL.
2. Обсяг даних однієї локації ≈ 30–40 МБ сирих → після конвертації (glTF + WebP/KTX2 + Opus) ≈ 8–15 МБ.
3. Найскладніше — **не графіка, а ігрова логіка та фізика**, які доведеться відтворювати за спостереженням.
4. Музики в наявних файлах немає — треба вирішити (див. [06-legal-and-risks.md](06-legal-and-risks.md)).
