# Формат B3D (Hard Truck 1)

Статус: ✅ **усі 12 файлів гри розбираються до останнього байта** (`tools/probe/b3d_parse.py`).
Джерела: специфікація HT2 від [reRNR/RNRFileFormats](https://github.com/reRNR/RNRFileFormats) (MIT) +
виправлення під HT1 за кодом завантажувача з `HTruck.exe` (адреси нижче).

## Заголовок
```
char[4]  "b3d\0"
u32      розмір файлу / 4
u32      зсув списку матеріалів / 4
u32      розмір списку матеріалів / 4
u32      зсув даних / 4
u32      розмір даних / 4
```
Матеріали: `u32 N`, `N × char[32]` — імена, шукаються в секції `MATERIALS` архіву RMP.

## Дані
`u32 111`, далі послідовність блоків, `u32 222`.

Блок: `u32 333`, `char[32] імʼя`, `u32 тип`, дані типу, [дочірні], `u32 555`.

**Дочірні** (у типів, позначених «+д»): `u32 кількість` (загальна), далі блоки.
У перемикачах (9, 10, 11, 21, 22, 29) дочірні розбиті на **групи**, розділені `u32 444`;
наприкінці можуть стояти порожні групи (`444` перед `555`) — завантажувач `0x43fb88`.

Фабрика блоків — `0x43c170` (switch за типом), читання даних — віртуальний метод класу `vtable+0x2c`.

## Базові структури
- `sphere` = 4×f32 (центр xyz + радіус) — обмежувальна сфера
- `vec3` = 3×f32
- **форма** (`0x44ad24`), вид задається типом блоку:
  | вид | дані |
  |----|------|
  | 0 | немає |
  | 1, 2, 5 | 4×f32 |
  | 3, 4 | vec3, vec3, f32, f32 |
  | 6 | `u32 n`, n × (`u32 k`, k×vec3) — полігони |
  | 7 | k×vec3 (k прочитано раніше) — ламана |
- **дані тригера** (`0x44b3d4`): `u32, u32, u32 n, n×u32/f32`

### Полігон (типи 8, 35)
```
u32 format_raw  (format = format_raw ^ 1)
f32, u32, u32 матеріал (індекс у списку матеріалів), u32 n
n × { u32 індекс_вершини, [uv × uv_count], [нормаль] }
use_uv  = format & 2; uv_count = ((format >> 8) & 0xff) + use_uv
use_normal = (format & 0x30) == 0x30; нормаль = vec3 якщо format & 1, інакше f32
```
