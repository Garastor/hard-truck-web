# 03. Архітектура веб-порту

## 1. Ключове рішення: реімплементація, а не емуляція

| Варіант | Плюси | Мінуси | Рішення |
|---------|-------|--------|---------|
| Емуляція Win32+DirectX у браузері (Boxedwine, v86 + Win98) | Оригінальна логіка 1:1 | Повільно на телефоні, DirectDraw/D3D5 погано емулюється, немає сенсорного керування, величезне завантаження | ❌ Лише як експеримент-довідка |
| **Власний рушій на TS + WebGL, що читає оригінальні ресурси** | Швидко на мобільних, сенсорний UX, PWA, можна покращувати | Логіку й фізику треба відтворити самим | ✅ **Обрано** |

## 2. Загальна схема

```
┌─────────────── OFFLINE (tools/, Node/Python) ───────────────┐
│ Game/Hard Truck/*.B3D *.RMP *.RES *.TCH *.OVL               │
│        │  Kaitai-парсери (спільні з runtime)                │
│        ▼                                                     │
│  converter:  B3D → glTF(.glb) + scene.json (логіка, шляхи,   │
│              кімнати, портали, тригери, колізії)             │
│              TXR/MSK/PLM → WebP/KTX2 атласи                  │
│              WAV → Opus/AAC; AVI → MP4                       │
│              TCH/INI → trucks.json                           │
│        ▼                                                     │
│  build/assets/<level>/…  + manifest.json (хеші, розміри)     │
└──────────────────────────────────────────────────────────────┘
        │  (варіант А: локальна збірка для себе)
        │  (варіант Б: конвертація в браузері з файлів гравця)
        ▼
┌──────────────────── RUNTIME (web/, браузер) ────────────────┐
│ AssetStore (OPFS/IndexedDB + Service Worker cache)           │
│ SceneLoader → Three.js сцена (кімнати/портали, LOD, небо)    │
│ Physics (Rapier): вантажівка raycast-vehicle + колізії світу │
│ Game: стан гри, заїзди/доставка, ШІ (по way-лініях), події   │
│ Input: touch / tilt / gamepad / keyboard → єдині «осі»       │
│ HUD: прилади з MSK-масок, мінікарта, меню (DOM/Canvas)       │
│ Audio: Web Audio — двигун (пітч), ефекти, 3D-джерела         │
└──────────────────────────────────────────────────────────────┘
```

Конвертер пишемо так, щоб **той самий TS-код** працював і в Node (CLI), і в браузері (Web Worker).
Це дає варіант Б — гравець підкидає свій `HardTruck.zip`, а конвертація відбувається на пристрої.

## 3. Модулі `web/src/`

| Модуль | Відповідальність |
|--------|------------------|
| `formats/` | Kaitai-згенеровані + ручні парсери: `rmp`, `txr`, `msk`, `plm`, `b3d`, `tch`, `ovl`, `ini` |
| `convert/` | Перетворення розібраних структур у Three.js/glTF, атлас текстур, матеріали (`tex/ttx/col/transp/env/rot`) |
| `assets/` | Імпорт файлів гравця (zip/папка), кеш OPFS, маніфест, прогрес завантаження |
| `render/` | Рендерер, камери (з кабіни / позаду / зверху), небо, туман, день/ніч, дощ, фари, LOD, портальне відсікання |
| `physics/` | Rapier world, модель вантажівки (двигун, КПП, гальма, зчеплення шин), колізії з дорогою/обʼєктами |
| `game/` | Ігрові режими, правила, події з B3D (`event_finish`, `restart_*`), ШІ-суперники, рахунок/гроші |
| `input/` | Абстракція керування; профілі: сенсор-кнопки, нахил, віртуальне кермо, геймпад, клавіатура |
| `ui/` | Меню, HUD, налаштування, локалізація (укр/рос/англ) |
| `audio/` | Двигун, ефекти, музика, мікшер |
| `platform/` | PWA, повноекранний режим, блокування орієнтації, Wake Lock, визначення потужності пристрою |
| `debug/` | lil-gui, перегляд сцени/блоків B3D, вільна камера, оверлей колізій |

## 4. Мобільна специфіка (основна платформа)

- **Цільові пристрої:** Android середнього рівня (≈2021+, Chrome) і iPhone 11+ (Safari 17+). Ціль — **60 FPS**, мінімум 30.
- **Роздільна здатність рендеру:** динамічна (`pixelRatio` 0.6–1.0 залежно від FPS); пост-ефекти — вимкнені за замовчуванням.
- **Керування (налаштовується):**
  - Пресет 1: ліва частина — кнопки ⬅️➡️ (або повзунок-кермо), права — газ/гальмо, зверху — КПП, вид, гудок, фари.
  - Пресет 2: нахил телефону = кермо, педалі на екрані.
  - Геймпад — автоматично при підключенні.
- **Памʼять:** ресурси однієї локації в RAM ≤ 150 МБ; текстури KTX2 (ETC/ASTC через Basis) або WebP з даунскейлом.
- **Завантаження:** покадрове/посекційне за кімнатами (`room_*`), прогрес-бар; повторні запуски — з OPFS миттєво.
- **iOS-нюанси:** Web Audio розблоковується лише жестом; DeviceOrientation потребує дозволу; повноекранний режим обмежений → PWA «на головний екран».
- **Енергозбереження:** пауза при `visibilitychange`, обмеження FPS у меню.

## 5. Принципи

1. **Парсери — з тестами на реальних файлах** (golden tests): кожен формат читається до останнього байта.
2. **Дані, а не код:** параметри вантажівок, матеріали, події — з файлів гри, не хардкод.
3. **Візуальна звірка з оригіналом:** для кожної локації — набір еталонних скріншотів з dgVoodoo2 vs порт.
4. **Ресурси гри ніколи не потрапляють у git і на публічний хостинг.**
5. **Мобільний перший:** кожна фіча перевіряється в мобільному вʼюпорті перед тим, як вважатися готовою.
