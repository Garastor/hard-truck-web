# 05. Робочий процес з Claude Code

## 1. Базові налаштування

- **`CLAUDE.md` у корені проєкту** — короткий контекст, який Claude читає в кожній сесії
  (мета, стек, команди, правила). Вже створено; оновлювати після кожної фази.
- **Пам'ять Claude Code** — фіксує рішення та вподобання між сесіями автоматично.
- **`.claude/launch.json`** (Фаза 0) — конфіг dev-сервера, щоб Claude міг сам запускати превʼю:
  ```json
  { "version": "0.0.1",
    "configurations": [{ "name": "web", "runtimeExecutable": "npm",
                         "runtimeArgs": ["run", "dev", "--prefix", "web"], "port": 5173 }] }
  ```
- **`.claude/settings.json`** — дозволи на типові команди (`npm run *`, `npx vitest`, `python -I tools/*`),
  щоб не підтверджувати кожну. Найпростіше — попросити Claude: *«налаштуй дозволи для npm і python у проєкті»*
  (скіл `update-config`), або запустити `/fewer-permission-prompts` після кількох сесій.

## 2. Як ставити задачі

Одна сесія = одна задача з roadmap. Шаблон запиту:

> **Фаза 2, задача «Матеріали з RMP».** Контекст: Docs/01-analysis.md §2.1.
> Зроби: підтримку `tex/ttx/col/transp` у `web/src/convert/materials.ts`.
> Готово, коли: CIRCUIT відкривається у превʼю без рожевих (відсутніх) текстур, тести зелені,
> скріншот у мобільному вʼюпорті.

Поради:
- Завжди вказуйте **критерій «готово»** — Claude сам перевірить його тестами/превʼю.
- Для великих задач просіть спершу **план** (Plan mode), потім реалізацію.
- Після завершення фази просіть оновити чекбокси в `Docs/04-roadmap.md` і `CLAUDE.md`.

## 3. Корисні можливості Claude Code для цього проєкту

| Можливість | Як використовуємо |
|-----------|-------------------|
| **Вбудований браузер** (preview) | Claude запускає `npm run dev`, робить скріншоти сцени, читає консоль WebGL-помилок |
| **Мобільна емуляція** (`resize_window: mobile`) | Перевірка сенсорного UI в 375×812, ландшафт |
| **Сабагенти** (`Explore`, `Plan`, `general-purpose`) | Паралельне дослідження форматів, огляд коду спільноти (ht2-rev, Blender-плагін) |
| **Worktree-ізоляція** | Експерименти (напр. Rapier vs cannon-es) в окремій гілці без ризику для main |
| **`/code-review`**, `/security-review` | Огляд перед злиттям фази |
| **`/simplify`** | Прибирання коду після швидких прототипів |
| **Hooks** | Напр. автозапуск `vitest` для `formats/` після редагування парсерів |
| **Artifacts** | Публікація звітів/дашбордів прогресу (за бажанням) |
| **Python/ffmpeg через Bash** | Зонди форматів, пакетна конвертація аудіо/відео |

## 4. Дослідження форматів разом з Claude

1. Claude пише зонд у `tools/probe/` (як `probe_b3d.py`) → виводить гістограми, приклади.
2. Ви запускаєте оригінал і кажете, що бачите в цьому місці (колір, обʼєкт) — Claude звіряє.
3. Висновки фіксуються в `Docs/formats/<формат>.md` (створювати в Фазі 1).
4. Тільки після цього — продакшн-парсер у `web/src/formats/` з golden-тестом.

## 5. Тестування на реальному телефоні

- `npm run dev -- --host` → відкрити `http://<IP-ПК>:5173` на телефоні в тій самій Wi-Fi мережі.
- Android: `chrome://inspect` на ПК для консолі/профайлера.
- iPhone: Safari → Розробка (потрібен Mac) або тимчасово — оверлей логів у debug-режимі гри.
- Для PWA/DeviceOrientation на iOS потрібен HTTPS → `vite --host` з `@vitejs/plugin-basic-ssl`.

## 6. Чого не робить Claude без вашого підтвердження

- Пушити в публічні місця, публікувати ресурси гри.
- Видаляти файли в `Game/`.
- Встановлювати глобальне ПЗ (запропонує команду — запускаєте ви).
