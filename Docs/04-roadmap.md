# 04. План робіт (Roadmap)

Кожна фаза завершується **демонстрованим результатом** у браузері (крім Фази 0–1).
Задачі сформульовані так, щоб їх можна було віддавати Claude Code як окремі сесії (див. [05](05-claude-code-workflow.md)).
Оцінки — орієнтовні, у «сесіях» Claude Code (≈1 сесія = 1–3 год. спільної роботи).
Позначки: `[x]` — зроблено, `[~]` — частково, `[ ]` — ні. Журнал: [progress.md](progress.md).

> **Паралельна доріжка R (реверс `HTruck.exe`)** описана в [07-reverse-engineering.md](07-reverse-engineering.md#4-план-реверсу-паралельна-доріжка-r).
> Звʼязки: R2 → Фаза 1–2 (блоки B3D), R3–R5 → Фаза 3 (фізика), R6 → Фаза 5 (логіка), R7 → Фази 4/6.

## Поточний порядок робіт (погоджено 2026-10-10)

1. ✅ **Межі траси** — колізії з обʼєктів `hit_*` оригіналу (огорожі, підлога, горби).
2. ✅ **Продуктивність на iPhone** (Фази 2/4): режими якості, обмеження кадрів, кеш файлів гри на пристрої.
   Портальне відсікання — якщо телефон і далі грітиметься.
3. **Фізика як в оригіналі** (Фаза 3, доріжка R4) — до ігрового циклу, щоб не перебалансовувати економіку.
4. **Ігровий цикл** (Фази 5–6): база `MENU3D`, економіка, профіль, збереження.
5. Далі за фазами: пошкодження/погода, меню/звук, реліз.

> **Рішення (2026-10-10):** під час розробки — http з ПК у домашній мережі. HTTPS-хостинг (повний офлайн через
> service worker) — лише на етапі релізу (Фаза 7). Файли гри вже кешуються на пристрої (IndexedDB).
