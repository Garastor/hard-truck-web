# Запуск оригіналу на Windows 11 (для телеметрії)

Стан на 2026-10-10. ПК: NVIDIA RTX 3070, 60 Гц. Гра — `Game/Hard Truck/HTruck.exe`.

## Що працює
- `truck.ini`: `hardacc=3dfx`, без dgVoodoo, шляхи `[INSTALL]` — на теку, з якої запускається гра
  (стояли на інше встановлення `D:\Games\Hard Truck` — тоді траса навіть не вантажилась).
- База (MENU3D) у кар'єрі працює; фізика оновлюється лише ≈ 5–6 разів/с (запис `re/telemetry/s6`, `s7`).

## Що не працює
| Конфігурація | Результат |
|---|---|
| `3dfx`, без dgVoodoo | траса вантажиться і рендериться, далі `f2pi(): param too large nan` у `_Car_V:run2` / `get_WheelsForces` |
| `3dfx` + dgVoodoo2 | падіння `0x4139d1` (обʼєкт екрана не створено — режим 3dfx шукає Voodoo) |
| `on` (Direct3D), з dgVoodoo або без | NaN у позиції машини одразу (запис `s8`), далі падіння `0x44dc0e` (індекс стека матриць з NaN) |
| `on` + обмеження NVIDIA 60 або 30 к/с | те саме |
| `3dfx` + обмеження NVIDIA 60 к/с | NaN на трасі |

## Гіпотези (не підтверджено)
- Гра бере час з `timeGetTime` (обгортка `0x4231c0`) і не викликає `timeBeginPeriod`: у режимі `on` кадри
  швидші за роздільність таймера → крок часу 0; у режимі `3dfx` ≈ 5 к/с → крок ≈ 0,18 с → жорстка підвіска
  (ks = 12500) розходиться. Обмеження кадрів драйвером не допомогло — або не діє на DirectDraw, або причина інша.
- Наступний крок, якщо знадобиться: налагоджувач (x32dbg) на `0x491558` (`f2pi`) — звідки приходить NaN.

## Висновок
Для порту достатньо бази + статичного аналізу коду; траси в оригіналі на цьому ПК поки недоступні.
