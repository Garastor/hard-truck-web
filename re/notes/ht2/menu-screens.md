# HT2: екрани меню LOAD.RES — графіка, керування, водії, записи

Реверс `king.exe` (Ghidra `re/king`, `re/decomp_king`, дизасемблер `gq.py disasm` — обробники кнопок і малювання цих
екранів Ghidra функціями не визначила). Код не копіювався — лише поведінка, координати й константи.
Перевірено макетами (картинки LOAD.RES, накладені за координатами з коду) — збігаються з гніздами фонів.

## 0. Спільне для всіх екранів меню
- **Система координат** — сцена 800×600, координати віджетів абсолютні (ті самі, що `SINGLE` у
  `web/src/games/ht2/ui/menu.ts`; перевірка: `s/canc` у коді (323, 485), `s/new` (323, 120), `s/arcad` (350, 174) —
  збігається з портом). Фон `<x>/back*.txr` 800×600 у (0, 0).
- **Накладки `*Opt`/`*Curr`/`*Rcnt`/`*Rec`/`*Replay`** — це фони панелей-контейнерів: та сама картинка, що й ділянка
  фону під ними (пікселі збігаються), малюється в прямокутнику панелі. Порту достатньо фону; накладку можна
  малювати поверх у вказаній точці (нічого не змінить). `*Opt.txr`/`*Rec.txr`/`*Replay.txr` — txr, `backDrivCurr`/
  `backDrivRcnt` — msk.
- **Конструктори віджетів** (усі (x, y) — лівий верхній кут):
  - 0x50ef60 — кнопка `<name>_a/_p/_ap/_f.txr` (стани: під курсором / звичайна / натиснута / недоступна);
  - 0x50e500 — кругла кнопка `.msk` (`aleft`, `aright`, `m/*`): `_a/_p/_ap/_f`;
  - 0x50e830 — перемикач (радіо) `.txr`: `_a`, `_p`, `_ap`, `_pp` (вибраний), `_ph` (вибраний під курсором), `_f`;
    5-й аргумент — вибраний на старті;
  - 0x50ec10 — кнопка-фіксатор (`r/rec`: має `_pp/_ph`) — натиснення шле id, віджати — id+1;
  - 0x50efb0 — повзунок: стрілки `aleft`/`aright` (.msk 29×29), бігунок `runner`; (x, y) — лівий верхній кут лівої
    стрілки, 7-й аргумент — повна ширина (права стрілка ≈ x + w − 29); значення 0…100;
  - 0x5c0550 — список зі скролом (`atop`/`abot`); поле введення — обʼєкт з vtable 0x64e160 (до 34 символів).
- **Підказки** (0x56ce40): затримка курсора над віджетом > 500 мс → табличка з `tip1_left/midd/right.msk` над
  курсором (y − 30; якщо < 0 — y + 10), текст по центру, шрифт `menublk.fon`. Текст — `mess.txt[id + 0x1A]` для
  id 101…999; id 2 («Отмена») — рядок 0x7E «игнорировать изменение»; id 1 — без підказки; id ≥ 1000 (рядки
  клавіш) — 0xAA «кликните для замены клавиши». Номери рядків нижче — індекси `tools/re/ht2/mess.py`.
- **Шрифти**: `DAT_006ced24` = `menu.fon`, `DAT_006ced28` = `large.fon` (0x50c900). Текст 0x5ea170: (x, y) — базова
  лінія; колір/режим (останні аргументи 4 чи 5) — не розібрано.
- **Круглі кнопки головного меню** (0x527f30) → екрани: `m/graph` (id 0x6B) — графіка, `m/contr` (0x67) —
  керування, `m/chang` (0x69, «ввести параметры игрока») — **водії**, `m/recor` (0x65) — записи.
- **Обробник екрана**: команда 2 = «Отмена» — відкат змін, повернення в головне меню; команда 1 — застосувати й
  закрити (кнопки «ОК» на цих екранах немає; ймовірно, вихід через круглу кнопку рамки / Enter — гіпотеза).
- Клік поза колом (центр (400, 327), радіус 240, 0x516bc0) передається головному меню (круглі кнопки рамки).
- Налаштування — `TRUCK.INI`, секція `[EFFECTS]` (крім `numdev` — `[ENV]`, і `[DRVn]`).

  екран? — гіпотеза); за замовчуванням 0x122, у TRUCK.INI гри 322 = 0x142.
- **«Автопоиск»** (0x516316 → 0x5159d0 → 0x515710): `maxdrv=3`, адаптер 0, скидає результати перевірки режимів

  потім 0x7B–0x7C «Видеорежим установлен. Сохранить?»; інакше записує `video`, `numdev`, `grf`, `dtl`.

### 1а. Що роблять повзунки «Спецэффекты» (`grf`) і «Детальность» (`dtl`)

**Зберігання.** `TRUCK.INI`, `[EFFECTS]`: `grf` (рядок 0x676d04) і `dtl` (0x676d10), цілі 0…100, за замовчуванням 100.
Читає їх **лише** конструктор екрана 0x515ca0 (поля обʼєкта екрана `DAT_006cec70`: +0x1a4 — grf, +0x1a6 — dtl;
обʼєкт створюється при старті меню, 0x527f30); записує — «Применить» і автопошук (0x515710). Повзунок — віджет
0x50efb0 → 0x5be8c0(max = 100, …): ціле 0…100 (short), бігунок на 182 px; крок стрілок не з'ясовано. Ключ `eff`
(0x676d14, автопошук пише 1023) **ніде не читається** — мертвий. `trafs`/`trafm` повʼязані з повзунками лише в
автопошуку (= grf·dtl/100), у грі — окремі повзунки насиченості трас.

Нижче g = grf/100, d = dtl/100 (множник 0,01 — 0x64c268).

якщо g > поріг_g **і** d > поріг_d (пороги 0 / 0,2 / 0,5 / 0,8 — 0x64c264/260/258/25c), інакше 0. Перевіряються

**B. Імовірності частинок пропорційні g** (без порогу; 0x696048 = 0x69605c = 0x696074 = 0x696078 = g):
- дим пошкодженої машини (0x4ba660 ← 0x551970): щокадру з імовірністю min(1, g + 0,2); при пошкодженні p ≥ 0,4:
  з імовірністю (p − 0,4)·1,667 чорний дим `msmoke`, інакше пара `mvapor`; при p > 0,7 ще вогонь `burn`;
- дим/вогонь/уламки обʼєктів, що вибухають чи горять (0x4ba310 `mnBlow2/3`, 0x4ba520, 0x4ba8a0, 0x4baae0):
  імовірність min(1, g + 0,1);
- світло від вогню `ThrowLamp` (0x4d9cd0 ← `mnFire`, одне на сцену): лише при g > 0,5.

**C. Деталізація dtl у рушії:**
- **GeometryKey** (0x512920): значення = 2 − ⌊dtl/35⌋ → dtl 0…34 → 2 (найпростіше), 35…69 → 1, 70…100 → 0
  (найдетальніше). Це перемикач B3D `refer_GeometryKey` (LOD причепів, `sky_sw` тощо); при 2 — небо
  `sky_min_cl`, інакше `sky_max_cl`; при 0 — ліміт пилу 200 замість 100 (0x4b9570).
- **LOD блоків 29** (0x5f9f20; поле камери +0x70 = dtl → контекст рендера [0x842] = 100 − dtl, 0x5eb310): метрика
  вибору рівня множиться на dtl/100 — режим 1: екранний розмір сфери × dtl/100 (рівень — найбільший i з
  values[i] < розміру; менше values[0] — не малюється), інші режими — відстанна метрика × dtl/100. Тобто з меншою
  деталізацією обʼєкти раніше спрощуються й зникають.
- **Додатковий прохід полігонів** (0x5af350): полігон з прапорцем матеріалу bit0 і порогом t (+0x32) малюється
  «повним» шляхом 0x5b22f0, якщо t < 0 або 100 − dtl < t, інакше простим 0x5b2950; у 0x5b22f0 для t < 0 ефект
  (env, біт 2 рендера) діє ближче за dtl·|t|/100. [Г] блиск/відбиття.
- **Тіні машин** (0x4bb270 → 0x57c490): рівень = max(рівень за відстанню, рівень за d): d > 0,75 → 0, > 0,5 → 1,
  > 0,25 → 2, інакше 3; за відстанню: < 20 м → 0, < 50 → 1, < 90 → 2, < 150 → 3 (далі — 2). Роздільність тіні:
  0 → 32, 1 → 16, 2/3 → 4 (0x579aa0). Тінь є завжди.
- **Кількість апаратних ламп** (0x512ea0 → 0x4cce70): 4 + 4·v/100 (4…8), v = dtl, а на HAL з T&L (0x7208d8) — grf.
- **Ліс/дерева** (`tree23`/`tree45`, обʼєкт `DAT_006f33b4`, 0x6144f0 з (g, d)): дальня сітка n = ⌊40·g·d⌋ клітинок
  на 750 (менше 5 → 0, вимкнено), ближня n = ⌊20·g·d⌋ на 250 (менше 5 → 0).

**D. grf у рушії (0x512920):** grf < 30 — вимкнено мипмапи (`DAT_007208c0` = 0; 0x5bae30 не просить
DDSD_MIPMAPCOUNT); grf < 60 — біт 0x2000000 у прапорцях рендера (`DAT_00702e8c` і світу +0xbcc): вимикає всі
багатотекстурні режими (0x5b04c0 обнуляє 0x7208bc/c4/cc/d0/d4, 0x5b1740 пропускає другий прохід); grf ≥ 60 —
дозволено. Окремо: якщо grf > 90, dtl > 90, якість текстур ≥ 3 і пристрій уміє режим 0x7208d4 — «складні» краплі
на лобовому склі з копією кадру (`DAT_007025b0`, 0x56d810 → 0x5a6160/0x5a6420; [Г] заломлення).

**Чого повзунки не змінюють** (шукав): дальність видимості й туман (камера +0x20 — 200/1000 від режиму, не від
повзунків), сліди шин (`trace`/`shadow`, 0x4bc690 — без умови), кількість трафіку (лише через автопошук `trafs`),
дзеркала. Ціль поля 0x2150 контексту рендера (= clamp((100 − dtl)·0,01, 0, 1), 0x5ae0e0) — не знайдено.

**Рівні (зведено):**

| Налаштування | Що додається |
|---|---|

| g > 0, d > 0 | вихлоп/кулі `Particles`, уламки `crPart` |
| + d > 0,2 | пара `mvapor` (0x4baf90) |
| + g > 0,2, d > 0,5 | хмари вибуху машин, бризки з-під коліс |
| + g > 0,2, d > 0,8 | пил з-під коліс, листя з дерев |
| g > 0,5, d > 0,2 | краплі на склі |
| g > 0,5, d > 0,5 | дощ, сніг, відблиски на мокрій дорозі, фари чужих машин, світло від вогню (g) |
| grf ≥ 30 / ≥ 60 | мипмапи / багатотекстурні проходи |
| grf > 90 і dtl > 90 | краплі на склі з заломленням |
| dtl 35 / 70 | GeometryKey 1 / 0, небо `sky_max_cl` |
| ліс | густота ∝ g·d (n < 5 → вимкнено: ближня сітка при g·d < 0,25, дальня — при g·d < 0,125) |

## 2. Керування — `c/backCtrl.txr` (0x513b30, малювання 0x514d10, обробник 0x514a40, перепризначення 0x515270)

## Що лишилось невідомим
- Точна базова лінія рядків таблиці керування (зсув від верху рядка) і кольори тексту (останні аргументи 0x5ea170).

- Формат `.tr`, `.pl1` (крім логотипа/фото), мініатюри в `.mvp`.
