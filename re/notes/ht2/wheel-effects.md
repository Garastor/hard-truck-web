[К] — код king.exe (адреса), [Д] — дані гри, [П] — памʼять запущеної гри (дамп Car_V, tools/re/ht2/carmode.py),

## 1. Сліди шин (`TraceNode`, aeffects.c)

**Система** (0x4bc690, створює 0x4b9570 при завантаженні світу й 0x4b9b90 при перезавантаженні — сліди стираються):
- матеріали `"%s%d"` від `trace` (2 шт.: **trace0**, **trace1** COMMON.RES) або `shadow` (shadow0/1), якщо
  DAT_006cec68 = 0 — текстурної памʼяті < 2 МБ (0x512ea0) [К]. COMMON.RES: `trace0 tex 25` = `trace.txr`
  (протектор «ялинкою»), `trace1 tex 26` = `trace1.txr` (поздовжні смуги ковзання), обидві 32×32, чорні з альфою
  ≤ 68/85 з 255 [Д];
- 20 слотів стрічок (за номером колеса, спільні для всіх машин), один `TraceNode` (кільце з 10 передбачено, але
  лічильник [+0x54] ніде не збільшується — завжди вузол 0) з двома буферами по **0x4b0 = 1200 вершин** (по одному на
  матеріал) → **200 відрізків** на матеріал, найстаріші перезаписуються; **згасання немає** [К 0x4bcd00, 0x4bd850,
  0x4bd760].

**Хто ставить прапорець** `ph+0x34d0+4i` (0x502780 — контакт колеса з поверхнею, щокроку; обнуляється на вході) [К]:
лише коли `ph+0x2740` ≠ 0 (0x4cf260/0x56fc10: [Г] машина з повною фізикою — гравець) і колесо на землі
(`ph+0x19a4+2i` = 0). Умова: (**ковзання вбік** `ph+0x19c4+i` ≠ 0 **і |α| > 10°** (0x64daa0 = 0,174533 рад,
α — `ph+0x1a30+4i`)) **або пробуксовка/блокування** `ph+0x19d4+4i` ≠ 0. За покриттям ([[contact+100]+4]):
- 1, 5 (асфальт), 8 — умова вище → 2;
- 2 (ґрунт) — та сама умова двічі: спершу → 1, тоді → 2 (асемблер 0x502ed8…0x502f33 однаковий; EBX = 2) — отже 2;
- 3 — те саме з |`ph+0x1a5c+4i`| > 0,2 замість |α| > 10° → 2;
- 4/7/9, 6/10/11 — слідів немає.
Тобто на практиці завжди **2 → trace1** (матеріал = прапорець − 1); `trace0` не вживається [К].

**Додавання** (0x548250 ← 0x54a380 make_new_Pos, щокадру машини): для кожного колеса з прапорцем — 0x4bcd00(контакт
колеса `ph+0x3510+0xd0·i`, ширина, колесо, тип):
- **ширина** — `ph+0x34f0+4i` = tech **front_wheel_thickness** (+0xb8) для коліс 0, 1, **rear_wheel_thickness**
  (+0xbc) для решти (0x4ebd00); якщо ширина колеса (i + 2) mod 4 менша — середнє з нею [К]. ZilR: 0,28 / 0,613 →
  передні 0,28, колеса 2–3 — 0,4465, 4–5 — 0,613 [Д];
- стан стрічки колеса: кадр (лічильник [світ+0xbb0]) пропущено → стан 0; 0 — запамʼятати точку; 1 — точка далі
  **0,2 м** (0x64c1e8) → перший відрізок; 2 — кожні ≥ 0,2 м відрізок зсувається (кінець → початок). Новий напрям
  проти попереднього: скалярний добуток < **cos 5** (0x695c54 ← FLD 5,0; FCOS у 0x4bc680 — 5 рад, ≈ 0,284) → стан 0;
- квад (0x4bd850, 6 вершин — два трикутники): кути початку — ± (n₀ × напрям попереднього відрізка)·w₀/2, кінця —
  ± (n₁ × напрям)·w₁/2 (стики без щілин); u = 0/1 упоперек, **v = 0 → довжина/w₁** (повтор на кожен відрізок);
  висота вершини — висота поверхні під нею (0x4bdf10: полігон 0x4be2c0 чи рельєф 0x616850; немає — z контакту)
  **+ 0,1 м** (0x64c1dc); нормаль (0, 0, 1).
- Рендер — вузол `_TDTN` (0x4bc950), до 10 буферів на матеріал.

## 2. Вихлоп (чорний дим зліва знизу ZiL)
Чорний дим = `msmoke` (середній колір 31/255; пил `dust` — світлий 173…193, пара `mvapor` — 191) [Д]. Єдиний
постійний викид msmoke біля машини — вихлоп 0x4bac90 у точках **SmokePosition/SmokePosition2** (objects.md
«Ефекти машин» §2). ZilR (запис tech 21): SmokePosition (−1,26; 0,2; −0,58), напрям (−0,99; −0,05; −0,1) — лівий
бік, низ, назовні; друга труба відсутня (0, 0, 20) [Д] — збігається зі знімком оригіналу.
- Умова: `car+0x51a4 & 2` (маса > 4000 і car_node не «daf…»; ZilR: [car+0x51a4] = 0x1fe [П]) **і** біт 0x400
  `car+0x27b4` = [car+0x51a0] ≠ 0 (0x54ff80). Поле `car+0x51a0` у коді читається **лише одним** звертанням
  (байтовий пошук disp32 0x51a0 у king.exe — 1 збіг, 0x55050c), запису немає; у памʼяті гравця на холостих
  [car+0x51a0] = 0, [car+0x27b4] = 0x181/0x189 [П]. Чим вмикається — не з'ясовано [Г: газ з Ctrl — за
  спостереженням користувача; потрібен запис памʼяті з Ctrl, `exh2.py`/`mon.py` у scratchpad сесії].
- 0x536100 ← 0x536360 (трафік): «пих» з 5 клубів (0x4bc2d0: швидкості ×0,5/0,8/1/1,2/1,5, msmoke чи mvapor з
  імовірністю 0,1 + r, при > 0,5 ще burn) протягом 1 с після мітки часу [+0x1d4] (поштовхи 0x531cc0/0x53b4c0) — для
  машин трафіку, не гравця [К].

## 3. Пробуксовка з Ctrl
- Ctrl+газ — **[0x2714] = 2** (1 — звичайний газ) [П дамп]: газ = t/(t + 0,2) (t — час утримання; звичайний —
  0,85·t/(t + 0,6)) і **обмеження «антибукс» 0x4ff660 оминається** (гілка `key ≥ 2` не йде на LAB_004ffc5d) [К 0x4ff800].
- Дамп Car_V (mode_20261018_012452_raw.bin) [П]: на 1-й передачі з газом 0,55…0,6 сила T = [0x1c94] ≈ 37…39 кН
  при Σμ·N ≈ 34…38 кН (μ [0x2670] = 0,72…0,77, асфальт) — уже на межі; з газом 0,99 T = 54…56 кН > 41 кН — буксують
  усі шість (0x4f3000 ділить тягу пропорційно μ·N — стан +1 у всіх ведучих одночасно). Пробуксовка в дампі коротка
  (3 кадри по 0,05 с): коли буксують усі ведучі, 0x4ff210 ставить оберти 3·g·n₀ (згладжено фільтром), момент на
  них ≈ 0 — сила падає нижче μ·N.
- Довгі дугові сліди на знімку оригіналу дає **ковзання вбік** у повороті з Ctrl: у дампі на 18 м/с з повним
  кермом trace = (2, 2, 0, 0, 0, 0) — передні колеса (α ≈ 0,6–0,7 рад).
