  FIRE_PROTECTION, EXTRA_TANK, FUEL, ANTI_RADAR, STEALTH_BODY_PAINT, HEADLIGHT_PROTECTION, AIR_FILTER_SNORKEL.
- У записі машини (`car+0x204 → +0x10`) — масив 19 × 16 байт: `+0` int — варіант (0 — немає, 1, для шин ще 2),
  `+8` double — «кількість» (за замовчуванням 1,0). Зсув рядка №k = 0x10·k (сканер №10 → 0xa0, скло №7 → 0x70).
  Копіювання туди/звідти — 0x476930 / 0x4769e0. Ціна обладнання (0x476980): Σ ціна_варіанта × double.

### 0.2. «Системи техстану» (TechSystem, 0x34 байти) [К 0x4eb460…0x4eb6e0]
Кожна система має для рівнів 0…2: `min[l]`, `max[l]`, `rate[l] = 1/life[l]`; стан `c ∈ [0, 1]`
(+0x24), поточний рівень `l` (+0x28), тип перенесення при зміні рівня (+0x30).
- значення (0x4eb5e0): **v = min[l] + (max[l] − min[l])·c**;
- знос (0x4eb6e0): c −= x·rate[l]; встановити стан (0x4eb6a0), задати значення (0x4eb600);
- зміна рівня (0x4eb4a0, `TechSystem::set_upgrade`): тип 0 — c := 1 (нова деталь), тип 1 — c := 0,
  тип 2 — зберегти абсолютне значення (перерахувати c), тип 3 — c не змінювати.

## 1. PR_FORCED_ENGINE — форсований двигун [К]
- Система двигуна A = M·(0,15 + 0,85·c) звичайний, M·(0,25 + 1,15·c) форсований: **нова — ×1,4 моменту** (+40 %),
  зношена — 0,25·M проти 0,15·M. Крива моменту T(n) = (A/B)·exp(…) (0x4ff460 → 0x507380; B — присадка §2).
- Тип 3: стан двигуна при встановленні не змінюється (не «новий двигун»).
- Знос двигуна з часом не знайдено; c падає від ударів (0x501010: −0,5 / −0,8 при деформаціях рівня 2 / 3) і
  при горінні (0x54e180: −dt/60 за секунду).
- Посібник: «увеличит мощность».

## 2. PR_OIL_ADDITIVE — присадка в масло [К]
- B = 1 (без) / **0,8** (з присадкою), від стану не залежить.
- Момент двигуна T ∝ A/B → **×1,25** (0x4ff460: друге значення — дільник).
- Витрата пального ∝ B (0x500612: знос бака = |n|·газ/n₀·B·dt) → **−20 % витрати**.
- Знос двигуна не зменшує (двигун з часом не зношується взагалі, §1) — опис у посібнику («снижает расход топлива и
  износ двигателя») код підтверджує лише щодо пального. Чи присадка «закінчується» — не знайдено (знос 0x3fc0 ніде
  не викликається, double №1 не змінюється).

## 3. PR_ABS — АБС / антипробуксовка [К частково]
- Лише рівень (`гравець+0x53cc` = рівень 0x53a4; через базу +0x10 — 0x53bc). 0x54ae44 (метод гравця 0x54a380)
  переписує рівень у три прапорці машини: `+0x2750`, `+0x2754`, `+0x274c`.
- **+0x2754 — антипробуксовка** (0x4ff800 → 0x4ffc1c): якщо прапорець (або глобальне налаштування `0x696c4c` разом
  із `+0x2740`) і не натиснуто клавішу вимкнення (`+0x2701`) — газ ≤ 0,9 · g_lim, де g_lim (0x4ff660) = 0,9 × частка
  газу, за якої сила тяги дорівнює межі зчеплення ведучих коліс (0, якщо не буксує — 1). Посібник: вимикається
  утриманням клавіші разом із газом [Г: це клавіша `+0x2701`].
- **+0x274c**: у кермі гравця (0x500850) лише скидає таймери при зміні `+0x2701`; у кермі автопілота/ШІ (0x4d74e0)
  вимикає обмеження кута керма за швидкістю. Ефект для гравця — мізерний [К].
- **+0x2750 — читача не знайдено** (лише запис 0x54ae66) → антиблокування коліс при гальмуванні в коді немає:
  блокування (0x4ee540, `physics.md`) не перевіряє жодного прапорця ABS [К за відсутністю].
- Знос: немає (діє лише рівень).

## 4. PR_ADJUSTABLE_SUSPENSION — пневмопідвіска [К]
- Множник s = 1 / **0,3**, від стану не залежить. Єдиний читач — метод гравця 0x554bb0 (слот vtable,
  0x64ceac…): H = |вектор удару| / `[+0x19c]` [Г: маса] × s → якщо H > 2, `hitPlayer` (0x446d20) псує вантаж:
  для кожного лота d = (1 − крихкість товару)·H·0,02 (d < 0,01 → 0, d > 1 → 1), якість лота ×(1 − d),
  повідомлення `X_DAMAGED`.
- Отже: **шкода вантажу від ударів ×0,3** (і поріг удару фактично ×3,3). На керованість/фізику підвіски не діє
  [К за відсутністю інших читачів]. Посібник: «лучшая сохранность хрупкого груза».

## 5. PR_BRAKES — вентильовані гальма [К]
- Система гальм: v = 0,1 + 0,9·c (звичайні) / **0,5 + 0,5·c** (вентильовані). Сила гальма колеса
  `[0x1c98+4i]` = v × базова (1,5 × статичне навантаження, `physics.md`) × (0,2 для коліс з прапорцем
  `[0x3e1c+0x14i]`) — 0x501930 (0x501a62…).
- **Нові гальма однаково сильні** (v = 1); різниця — повільніший знос (life 120 проти 60) і вищий мінімум
  зношених/перегрітих (0,5 проти 0,1).
- Знос (0x4f35f0, коли педаль гальма > 0,1, `+0x1abc`): обидві системи 0x3f58 і 0x3f8c −W, W ∝ час·|v|/(|v| + 5)
  [точна формула — 0x4f385c]; без гальма 0x3f8c відновлюється (знос × −5). Якщо 0x3f8c ≤ 0 — **стан гальм := 0**
  (0x4f38bc). 0x3f8c [Г] — «запас нагріву» гальм (у таблиці назв відповідає `transmiss`; при 0 ставить стан
  `+0x3c18 = 2` у 0x4ff978 — [Г] дим/звук перегріву); покращенням не змінюється.

## 6. PR_ENGINE_BRAKE — гальмо двигуном [К]
- E = 0 (без) / 0,25·c_f…2·c_f (з покращенням; знос нульовий → c = 1 → **E = 2·c_f**).
- Момент гальмування двигуном (0x4ff3e0 → 0x507360): T_br(n) = −n·c_f − n·E·√b, b — педаль гальма `[0x29dc]`;
  на нейтралі (`[0x1c28]` = 1) — 0. Разом із тягою: T = g·T(n) + (1 − g)·T_br(n) (g — газ).
- Тобто без покращення двигун гальмує лише тертям −n·c_f; з ним **при натиснутій педалі гальма додається
  −2·c_f·n·√b** — гальмування двигуном до ×3 при повному гальмі (передається на ведучі колеса через трансмісію).

## 7. PR_REINFORCED_CHASSIS — посилена рама [К]
- Множник r = 1 / **0,3** (від стану не залежить). Читач — метод гравця 0x554c20 (база гравець+0x10,
  `[ESI+0x5290]`): вектор імпульсу удару ×r **на самому початку** обробки зіткнення → від нього залежить усе:
  поріг і сила деформацій зон (0x591660), займання від удару (0x549900), шкода двигуну/системам (0x501010).
- Порт (−40 %) — неточно: в оригіналі **×0,3 імпульсу удару**.

## 8. PR_BULETPROOF_GLASS — броньоване скло [К] (виправлення до `police.md` §5, `helicopters.md` §5, `mafia.md` §8)
- Скло g = 2 − c (звичайне: нове 1, зношене до 2) / 1 − 0,8·c (броньоване: **нове 0,2**). Стан скла ніщо не
  зношує (знос 0x5308 не викликається), тож фактично g = 1 / 0,2.
- 0x567440 (влучання кулі; `EBP = гравець+0x5308`, три виклики 0x4eb5e0 — 0x567907, 0x567986, 0x5679c2) — те, що в
  нотатках названо «параметром складності», — **це скло**:
  - шкода/поштовх: вектор удару × g·40 → метод машини `+0xa4`;
  - **займання** з імовірністю p = g·P·0,03/(P + 0,3) (P — сила пострілу: міліція/мафія 0,1 → 0,0075·g,
    гелікоптер 2,0 → 0,026·g); гілка з 0,2 замість 0,03 (умова «x > |x|») ніколи не виконується.
- Отже броньоване скло: **шкода від куль ×0,2 і займання від куль ×0,2** (міліція 0,15 % за влучання,
  гелікоптер ≈ 0,5 %). Посібник: «уменьшающие повреждения… из оружия мафии и милиции».
- Займання від куль/ударів повністю не запобігає ніщо; гасить — пожежна система (§12).

## 9. PR_HEADLIGHT_PROTECTION — захист фар [К]
- Лише рівень; читач — 0x554c20 (зіткнення, `[ESI+0x5424]` = гравець+0x5434): якщо є захист, кількість деформації
  для зон **1, 2, 3** ×0,2 (0x554f4d, 0x554fca, 0x55502d → 0x591660); зони 6, 7, 8 — без змін.
- Фари гасне при деформації зон (0x546d10 читає зони 6 і 7 — `[+0x2540]+0x7c/+0x90`, лампи `0x6d211c…`) —
  котрі зони передні, а котрі задні (стоп-сигнали) — [Г]: імовірно, зони 1–3 — передок із фарами.
- Пошкоджене `up_hlights_0` на F3 за порогом — не розібрано.

## 10. PR_AIR_FILTER_SNORKEL — повітрозабірник [К + Д]
- Читач — обробник тригерів біля гравця 0x4ce300 (колбек із 0x4cf620): тригер виду **0x10** з параметром h
  (float) — рівень води. Якщо є шноркель (рядок №18 таблиці, не система) — h −= **1,0 м** (0x64c250). Якщо
  висота початку координат машини (z матриці `+0x2c` вузла гравця) < h — гравцеві ставиться прапорець 0x20000
  (0x4ce2e0 → 0x446c80), за яким `killDelayedPlayers` (0x446af0) **вибуває гравець** («утонул», [Г] щодо екрана).
  Той самий наслідок має тригер 0xcc0 (без перевірки висоти).
- Дані [Д]: блоки 13 з тригером `i1 = 16` (`water_<рег>_<nnn>` і безіменні) — ≈ 142 штук у `ENV/*.b3d`, рівні
  0; 0,5; 2; 4; 7; 9; 10; 14 м (сфера блоку — зона дії).
- Отже: **шноркель дозволяє заїхати на 1 м глибше** у воду, і все. На двигун/опір у воді не діє.
  Посібник: «Позволит вам преодолевать неглубокие водные преграды».

## 11. PR_HORN — сигнал [К]
- Лише рівень (`гравець+0x5364`): 0x543bb0 вибирає звук сигналу — з покращенням `hornupgrSound`, без нього
  `hornSound` (якщо маса з tech ≥ 4000) або `carhornSound` (0x53fdb0). Грає 0x538370 при натиснутій клавіші:
  у кабіні — 0x4e5140 (гучність 15), зовні — 3D-звук 0x5fd430.
- **На трафік не впливає**: стан натиснутого сигналу ніде не зберігається, ШІ його не читає [К за відсутністю;
  перевірено читачів 0x530070 і прапорця `+0x578` — це перемикач виду з кабіни]. Перемикач моделі `HornKey`
  (гравець+0x5018) знаходиться в 0x5427a0, але не використовується.

## 12. PR_FIRE_PROTECTION — протипожежна система [К]
- Система: 0 зарядів (без) / до **4** (life 4, c = 1 → 4). Горіння (0x54e180): двигун −dt/60, бак −0,2·dt/60 за
  секунду; коли від займання (`+0x5444`) минуло > **5 с** (0x64b6d0) — 0x5494c0(0): якщо є система і заряд > 0 —
  мінус 1 заряд, гасіння (0x549b90) і звук для гравця; якщо зарядів стало 0 — пейджер `mess 100` [Г: «система
  вичерпана»]. Паралельно в записі машини double рядка №12 −0,25, на ≤ 0 — варіант := 0 (покращення зникає).
- Отже **4 автоматичні гасіння** (посібник каже «трех возгораний»), кожне через 5 с після займання.
  Ремонт на СТО (0x555550…0x555a70) гасить незалежно від системи.

  1,5 5 5] (f_r = |…|·A + |…|·B) — від шин не залежить. Яка поверхня — асфальт/ґрунт/пісок, — не зʼясовано
  ([Г]: 1, 5, 10 — тверді дороги; 2, 3, 11 — бездоріжжя); 12–13 — μ = 0 і великий опір.
- Знос шин — за пройденою відстанню (0x4f6860): v_шин = 0,6 + 0,4·c звичайні (life 30000), 0,8 + 0,2·c
  покращені (60000).

  ще поводяться як режим машини `[0x276c] ≠ 0`: інша модель пружин коліс (0x4f8260: модуль сил, мʼякше
  обмеження ходу), гойдання кабіни ×0,3 (0x535a70).
- **Позашляхові (2)**: μ на 2 → 0,8 (з 0,55), 3 → 0,4, 11 → 0,8 (і в дощ не падають), на 1 як звичайні.
  Задумане зменшення опору кочення ×2/3 на поверхні 2 (0x502e31) перевіряє **значення** шин == 2,0 замість
  варіанта — умова ніколи не виконується [К].
- Посібник: шосейні — «на асфальте на больших скоростях и в дождливую погоду», вездеход — «проходимость на бездорожье».

## Вибування гравця (кінець гри) [К + Д]
Кінець гри — це **відеоролик** (`*.bne` у корені гри — звичайні AVI Indeo5 640×480 зі звуком), після нього —
**вікно результату** на весь екран (клас 0x51eea0, глобальний 0x6ceca8; показ — 0x51f380(режим)).

### Причини і ланцюжок
| Причина | Де виявляється | Ролик (режим 0x5279e0) | Вікно (режим 0x51f380) | Картинка |
|---|---|---|---|---|
| Машина знищена: пошкодження 0x555500 **> 0,9** (0x64c958) | щокадровий метод 0x597b00 (0x598409) [Г «щокадровий»] | `trirr.bne` (2) | 0 | `BackLoose2` «КОНЕЦ ИГРЫ — ВОССТАНОВЛЕНИЮ НЕ ПОДЛЕЖИТ» |
| Утонув: тригер 0x10, z машини < h | клієнт 0x56ffd0 (0x570880) → прапорець 0x6f3428 := 1 | `trirr.bne` (2) з 0x569650 | 0 | `BackLoose2` |
| Тригер 0xcc0 (без перевірки висоти) | 0x56ffd0 → 0x6f3428 := 1 | `trirr.bne` (2) | 0 | `BackLoose2` |
| Банкрут: гроші гравця (+0x88) **< 0** | таймер `SeeIfBankrupted` (0x426fc0/0x427020, кожні **8 с**) → прапорець 0x10000 і подія **0xc** | `trbn.bne` (4) | 5 | `BackLoose5` «ВЫ БАНКРОТ» |
| Інший гравець захопив ринок | подія 0xc для чужого гравця (0x4d80e7) | — | 1 | `BackLoose1` «РЫНОК ПЕРЕВОЗОК МОНОПОЛИЗИРОВАН ВАШИМ КОНКУРЕНТОМ» + таблиця «РЕЙТИНГ» |
| (перемога) гравець захопив ринок | подія 0xc для свого гравця без 0x10000 | `TRw1.bne` (3) | 2 | `BackWin` «ПОЗДРАВЛЯЕМ! ВЫ ЗАХВАТИЛИ РЫНОК ПЕРЕВОЗОК РЕГИОНА!» |
- Ролики `trp.bne` (міліція, арешт), `trml`/`trmm.bne` (мафія) і `TRw.bne` (кубок) грають з режимом **5** —
  після них гра **продовжується** (0x528eaa…), це не вибування. **Арешт — не кінець гри** [К 0x56ad20].
- Відповідність «режим ролика → вікно» — кінець ролика 0x528ca0: 2 → вікно 0, 3 → 2, 4 → 5, 5 — повернення в гру.
- Вікна 3/4 — результати гонки/мережевої гри (меню Esc, 0x511c60, 0x576660): виграш — `BackWin1` (< 2 гравців) чи
  `BackWin2`, програш — `BackLoose3` «РЕЗУЛЬТАТЫ ГОНОК — ВЫ ПРОИГРАЛИ» чи `BackLoose4` «РЕЗУЛЬТАТЫ ИГРЫ».
- Вода/0xcc0 з клієнтського обробника — лише коли гравців ≤ 1 (`гра+0x514`), тобто в одиночній грі. Клієнтська
  перевірка глибини **без поправки шноркеля** (0x570885 порівнює z з h напряму) — на відміну від серверної 0x4ce300
  (§10, h − 1 м) [К]; отже в одиночній грі шноркель, схоже, від кінця гри не рятує [Г: порядок двох обробників].
- `killDelayedPlayers` (0x446af0) → `killPlayer` (0x4466a0) — **не екран кінця гри**: прибирає учасника зі світу
  (прапорець 0x40000, зняття замовлень/найманців, подія **7** клієнтам → 0x4d76b0 видаляє машину). Працює для будь-
  якого учасника (і ШІ: 0x420ed0, 0x421c00 — далекі/зайві боти). Затримки немає: прапорець 0x20000 обробляється в
  найближчому проході серверного циклу (0x42d6e0) [К]. Для гравця в одиночній грі паралельно спрацьовує шлях
  через 0x6f3428 → ролик → вікно.
- Ролик грає лише якщо файл відкрився (0x5279e0 повертає 0 — тоді ні ролика, ні вікна) [К].

### Згорання / вибух
- Окремого прапорця «згорів» немає. Знищення — лише через сумарне пошкодження 0x555500 > 0,9: Σ|sᵢ|·wᵢ, де s —
  9 зон деформації (`+0x2540`, крок 0x14) і 27 станів систем машини й причепа (0x5014b0), ваги — гравець+0x28c0
  (4 стани гравецьких систем і +0xb8 у суму не входять) [К 0x546a30, 0x542530].
- Горіння (0x54e180) знижує двигун/бак; чи доводить воно саме по собі суму до 0,9 — [Г], не перевірено.
- Вибух `_Blow` (0x549e60, викликає 0x551970 під час горіння, стан вогню 1/2) — ефект 0x4bc4d0 і, в одиночній
  кар'єрі (гравців < 2, `+0x524` = 0), **додаткове пошкодження** 0x555550(−0,4) [К; величина в сумі — Г]. Якщо після
  цього сума > 0,9 — `trirr.bne` → `BackLoose2`. Окремого «згорів» ролика/картинки немає.

  меню); **«Начать сначала»** у кар'єрі — 0x5c4340, перезапуск світу 0x4e06f0 (гравця 0x6d2078 := 0, скидання стану)
  і повернення у вікно гри [Г: нова кар'єра з початку]; **«Продолжить»** (лише перемога) — повернення в гру.
  Клавіші — стандартна обробка вікна 0x5d8bb0 (лише режими 0–2, 5 у кар'єрі); автозакриття/таймера немає [К за
  відсутністю].

### Збереження
- Збереження — `*.pl1` у корені гри (напр. `ВОДИТЕЛЬ.pl1`, 0x51bfa0/0x571f20). Код вибування й вікна результату
  збереження **не пише й не видаляє**: `DeleteFileA` (0x631d1d) викликають лише тимчасові файли інтерпретатора
  S-виразів (0x62b3c0…) [К за відсутністю]. Отже файл лишається як був на момент останнього запису, і з головного
  меню кар'єру можна завантажити знову (до вибування) [Г щодо інтерфейсу завантаження].

### Режими
- Кар'єра (`гра+0x524` = 0, гравців ≤ 1): усі причини вище; звук youlost/youwin за режимом.
- Інші режими (`+0x524` ≠ 0 — гонка/мережа [Г]): вода й 0xcc0 через клієнта не діють (гравців > 1), вибух не
  додає пошкодження; пошкодження > 0,9 → `trirr.bne` діє в будь-якому режимі [К 0x598405 без перевірки режиму];
  результати — вікна 3/4 з виграшем/програшем за 0x574530 (`DAT_0067b75c`); у мережі 0xa3 шле повідомлення 0x3b8,
  0xa8 — 0x3ba (перезапуск гонки).
