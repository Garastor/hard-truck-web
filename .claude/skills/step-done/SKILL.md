# Закриття кроку

1. **Перевірки** (з кореня репозиторію; Node може бути поза PATH):
   ```bash
   export PATH="/c/Program Files/nodejs:$PATH"
   (cd web && npx tsc --noEmit) && npm test --prefix web
   ```
   Помилки — виправити, не комітити зламане. (Хук `.githooks/pre-commit` робить те саме — не обходити `--no-verify`.)
2. **Перевірено в грі?** Для змін рендеру, фізики, інтерфейсу — скіл `verify-in-game` (якщо ще не зроблено).
3. **Журнал** — `Docs/ht1/progress.md` (перша гра), `Docs/ht2/progress.md` (друга), `Docs/progress.md` (спільний
   рушій, оболонка, структура): дописати пункт(и) в поточний розділ дати (`## РРРР-ММ-ДД — тема`; новий розділ, якщо
   змінилася тема чи дата). Стиль: коротко, що змінилось для гравця і чому; гіпотези позначати («гіпотеза»,
   «на око»); адреси HTruck.exe — якщо брали з реверсу. Не дублювати те, що вже записано.
4. **План** — `Docs/ht1/roadmap.md` / `Docs/ht2/plan.md`: оновити чекбокси/рядки, якщо крок закриває пункт.
   Формат B3D чи нові знахідки реверсу — у `Docs/formats/b3d.md` / `re/notes/ht1|ht2/*.md`.
5. **Коміт** — лише свої зміни. У тій самій теці можуть працювати інші сесії (наприклад, над іншою грою): їхні
   незакомічені файли не мають потрапити в твій коміт. Тому `git status`, далі `git add` **конкретних файлів** кроку
   (не `-A`, не `.`, не цілі теки на кшталт `web/src`; хук `.claude/hooks/git-guard.py` такі команди блокує). Після
   коміту — `git show --stat HEAD`: чужих файлів там бути не повинно (якщо є — `git reset --soft HEAD~1`,
   `git restore --staged <чужі>`, закомітити знову). Ресурси гри не додавати.
   ```bash
   git add web/src/games/ht2/ui/tablo.ts Docs/ht2/progress.md  # перелік файлів кроку
   git commit -m "<Що змінилось для гравця, українською; деталі через ;>

   Co-Authored-By: <рядок атрибуції з системного нагадування>"
   ```
   Повідомлення без `\/` та інших екранувань. Не пушити й не публікувати без прохання.
6. Коротко сказати користувачу: що зроблено, як перевірено, хеш коміту, що лишилось гіпотезою.
