# Завдання в окремих сесіях

## 1. Спершу — спитати, що винести (типово все тут)
Користувач дав список завдань → **до будь-якої роботи** одним рядком сказати, як буде, і спитати
(`AskUserQuestion`, `multiSelect: true`, варіанти — завдання списку коротко, до 4; більше — двома питаннями):

> «Завдання, які ти вибереш, піду в окремі сесії — кожна у своїй гілці (git worktree) і зі своїм dev-сервером на
> окремому порту. Решта — тут, по черзі, в цій сесії.»

- **Нічого не вибрано / «Other» без вибору — усе робиться тут**, послідовно (типовий варіант).
- Користувач прямо сказав «запусти сесії для всього» — не питати, усі в окремі сесії.
- «Агентів» користувач зазвичай має на увазі сесії — уточнити тим самим питанням, а не запускати субагентів.

## 2. Запуск кожної вибраної сесії
`mcp__ccd_session__start_session`:
- `initiation: "user_asked"`, `context: "fresh"`, **`use_worktree: true`**, `branch_name` — короткий slug
  (`ht2-radar-detector`), `name` — те саме;
- перед серією викликів — `mcp__ccd_session__mark_chapter`, перед кожним — жирний рядок-назва й одне речення;
- `prompt` — завдання за шаблоном нижче; `background` — спільний абзац (нижче), однаковий для всіх.

Порти: кожній сесії — **свій**, 5180, 5181, 5182… (по порядку запуску в цьому повідомленні; 5173/5174 — основна
копія, 4173 — превʼю збірки). Номер порту вписати в бриф явно.

### Шаблон брифу (`prompt`)
```
Завдання (HT1|HT2): <що зробити, скарга користувача дослівно, як відтворити, знімки — абсолютні шляхи>.

1. Прочитати CLAUDE.md і документи теми: <Docs/…, re/notes/…>. Код: <файли/модулі>.
2. <як зʼясувати причину / що порівняти з оригіналом>.
3. <що виправити; невідоме — гіпотеза; власні ефекти — лише зі згоди користувача>.
4. Перевірити в грі на СВОЄМУ dev-сервері (розділ «Середовище» нижче), знімки.
5. Коміт коду в свою гілку. Документи (Docs/, re/notes/, CLAUDE.md) у гілці НЕ правити — їх оновлює скіл `done`
   уже в main після злиття; у звіті — що записати (документ теми, журнал Docs/ht1|ht2/progress.md).
Готово — коли <критерій>; далі користувач скаже /done.
```

### Спільний абзац (`background`) — підставити порт і гілку
```
Hard Truck Web — порт ігор Дальнобойщики (HT1, HT2) у браузер (TypeScript, Three.js, Rapier), основна платформа —
телефон. Усе — українською (спілкування, коментарі, коміти). Ти працюєш у власному git worktree на своїй гілці
(не main): комітити лише в неї (`git commit -m … -- <файли>`), не перемикати гілок, не зливати в main, не пушити.

Середовище worktree:
- Файлів ігор (Game/) у worktree немає — їх дає основна копія: HT_GAME_ROOT="D:/Claude/Games/Hard Truck/Game".
- Один раз: `cd web && "C:/Program Files/nodejs/npm.cmd" ci`.
- Тести й коміт (pre-commit хук запускає tsc і vitest): `export PATH="/c/Program Files/nodejs:$PATH";
  export HT_GAME_ROOT="D:/Claude/Games/Hard Truck/Game"` у тій самій команді, що й `npm test`/`git commit`.
- Dev-сервер — ЛИШЕ свій, порт <PORT>: додати в `.claude/launch.json` СВОГО worktree конфігурацію
  {"name": "web-<PORT>", "runtimeExecutable": "cmd", "runtimeArgs": ["/c", "set HT_GAME_ROOT=D:/Claude/Games/Hard Truck/Game&& \"C:/Program Files/nodejs/npm.cmd\" run dev --prefix web -- --port <PORT> --strictPort"], "port": <PORT>}
  і `preview_start({ name: "web-<PORT>" })`. Цю правку launch.json не комітити (наприкінці
  `git checkout -- .claude/launch.json`). Чужі сервери (5173, 5174, інші 518x) не зупиняти й не використовувати.
- Запуск гри на своєму порту — скіл `launch-own-port` (розмір вʼюпорта ДО завантаження: у схованій панелі HT2
  падає на старті й лишається в меню; очікування циклами ≤ 35 с). Перевірка — `verify-in-game` з адресою
  http://localhost:<PORT>/…, окрема вкладка,
  `&mute`. Свій порт — окреме походження: localStorage/IndexedDB порожні й не ділять збереження з користувачем
  (потрібна кар'єра — нова гра чи тестове збереження через `window.ht2`); вкладок користувача не чіпати.
- Документи (Docs/, re/notes/, CLAUDE.md) у гілці не правити: паралельні гілки конфліктували б у журналах. Їх пише
  скіл `done` в main після злиття.
- Наприкінці: зупинити свій сервер (`preview_stop`), закрити вкладки. У звіті — назва гілки, коміти, що перевірено,
  що ні, що записати в документи. Злиття в main, документи й видалення worktree і гілки — скіл `done`, коли
  користувач скаже /done (сам не зливати).
```

## 3. Що робить ця сесія далі
- Невибрані завдання — тут, по черзі (`update_plan` з усім списком; винесені — кроками з `session`).
- Завершення сесій приходить нотатками. Звіт — не доказ: переглянути `git log main..refs/heads/<гілка>` і
  `git diff --stat main...refs/heads/<гілка>`.
- **Зливати в main — лише коли користувач скаже**: /done у самій сесії-виконавці або тут («злий гілки»). Злиття,
  документи в main, видалення worktree й гілки — скіл `done` (тут — по одній гілці, перевірка після кожної). Після —
  коротка таблиця «завдання → результат → гілка/коміти», нагадати про `git push` (пушить користувач).
- Без /done сесія-виконавець нічого не зливає й не пушить.

## Чому так
- Спільна тека (без worktree) — спільний індекс git і один dev-сервер: Vite перезавантажував вкладки всіх сесій і
  користувача, кілька сесій правили `drive.ts` одночасно, тестові вкладки ділили localStorage зі збереженнями
  користувача (доводилося копіювати й відновлювати). Окремий worktree + порт це прибирають.
