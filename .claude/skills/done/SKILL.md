# Злиття гілки в main і прибирання

Виклик `/done` (чи «зливай») — і є дозвіл користувача злити гілку в main. Не пушити: `git push` робить користувач.

Позначення: `MAIN` = `D:/Claude/Games/Hard Truck` (основна копія, гілка `main`), `WT` = тека worktree сесії
(`git rev-parse --show-toplevel`), `BR` = гілка (`git branch --show-current`). У bash на початку кожної команди:
```bash
export PATH="/c/Program Files/nodejs:$PATH"; export HT_GAME_ROOT="D:/Claude/Games/Hard Truck/Game"
```
Сесія з основної копії (не з worktree) — `BR` і `WT` взяти з `git worktree list`, решта так само.

## 1. Гілка готова
1. `git -C "$WT" status --short` — незакомічене своє закомітити поіменно (`git commit -m … -- <файли>`);
   тимчасову правку `.claude/launch.json` (сервер на своєму порту) — відкинути: `git checkout -- .claude/launch.json`.
   Документів (`Docs/`, `re/notes/`, `CLAUDE.md`) у гілці бути не повинно — вони пишуться в main на кроці 3; якщо вже
   є в комітах гілки — не страшно, злиються разом.
2. Влити свіжий main у гілку: `git -C "$WT" merge main`. Конфлікти — розвʼязати, не відкидаючи чужих змін main.
3. Перевірити в `WT`: `(cd web && npx tsc --noEmit) && npm test --prefix web`. Червоне — виправити й закомітити в
   гілку, не зливати зламане.
4. Зупинити свій dev-сервер (`preview_stop`) і закрити свої вкладки браузера.

## 2. Злиття в main
1. `git -C "$MAIN" branch --show-current` — має бути `main` (інакше зупинитись і спитати).
2. `git -C "$MAIN" status --short` — у основній копії можуть бути незакомічені файли інших сесій: їх **не чіпати**
   (без `stash`, `reset`, `checkout`). Злиття їм не заважає, якщо не зачіпає тих самих файлів; git відмовить —
   зупинитись і сказати користувачу, які файли заважають.
3. `git -C "$MAIN" merge --no-ff refs/heads/$BR -m "Злиття $BR: <що зроблено, одним рядком>"` (з рядком
   `Co-Authored-By`, як у звичайних комітах). Конфлікт (main встиг змінитись) — розвʼязати в `MAIN`, перевірити.
4. Перевірка в `MAIN`: tsc і тести (хук pre-commit на merge-коміт не запускається — запускати самому).

## 3. Документи — у main
Документи оновлюються в основній копії після злиття, не в гілці (інакше паралельні гілки конфліктують у журналах):
- тематичний посібник (`Docs/ht2/*.md`, `Docs/ht1/*.md`, список — CLAUDE.md «Ключові документи»): змінені файли,
  числа «де крутити», як перевірити, відступи від оригіналу; знахідки реверсу — `re/notes/ht1|ht2/*.md`;
- журнал `Docs/ht1|ht2/progress.md` (рушій і структура — `Docs/progress.md`): розділ `## РРРР-ММ-ДД — тема` — що
  змінилось для гравця, чому, як перевірено, що ні; план (`Docs/ht2/plan.md`, `Docs/ht1/roadmap.md`) — чекбокси;
- коміт у `MAIN` лише цих файлів поіменно: `git -C "$MAIN" add <нові файли>` (лише нові, поіменно) і
  `git -C "$MAIN" commit -m "Docs: …" -- <файли>`; `git -C "$MAIN" show --stat HEAD` — чужого немає.

## 4. Прибирання
1. Worktree: якщо сесію створив застосунок (тека поза `MAIN/.worktrees`), спершу спробувати
   `mcp__ccd_host__clean_up_worktrees` / `ExitWorktree` (ToolSearch); інакше —
   `git -C "$MAIN" worktree remove "$WT"` (відмовляє через незакомічене — подивитися, що там; `node_modules` і
   `dist` ігноровані й не заважають; `--force` — лише якщо там справді лише сміття збірки).
2. Гілка: `git -C "$MAIN" branch -d $BR` (`-d`, не `-D`: не видалить, якщо щось не злито — тоді зʼясувати чому).
   Гілка була на GitHub — віддалену не видаляти без прохання користувача.
3. `git -C "$MAIN" worktree prune`; `git -C "$MAIN" log --oneline -5` — злиття й документи на місці.
4. Після видалення `WT` робоча тека сесії зникає — далі команди лише через `git -C "$MAIN"`, сесію можна архівувати.

## Звіт
Одним абзацом: що злито (гілка, коміти, merge-коміт), перевірки (tsc, тести), які документи оновлено, що видалено,
що лишилось неперевіреним (наприклад, на телефоні) і нагадування: на сайт — після `git push`.
